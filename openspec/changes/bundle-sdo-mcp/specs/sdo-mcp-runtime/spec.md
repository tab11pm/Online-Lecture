# Spec Delta

## Purpose

Определяет, как приложение получает и запускает SDO MCP и как сообщает пользователю о неудачном запуске.

## ADDED Requirements

### Requirement: SDO MCP поставляется как зависимость

Приложение SHALL получать SDO MCP через зависимость `sdo_mcp`, закреплённую на теге `tab11pm/sdo-mcp`, и MUST NOT требовать от пользователя клонирования, сборки или установки Node.js.

#### Scenario: Установка зависимостей
- **WHEN** разработчик выполняет `npm install` в чистой копии репозитория
- **THEN** в `node_modules/sdo_mcp` присутствует собранный `dist/index.js`

### Requirement: Порядок выбора команды сервера

Конфигурация MCP SHALL выбирать команду в порядке: `SDO_MCP_SERVER_PATH`, установленный пакет `sdo_mcp`, `~/.local/bin/sdo-mcp`, `sdo-mcp` из PATH, и сохранять выбранный источник.

#### Scenario: Переопределение для разработки
- **WHEN** задан `SDO_MCP_SERVER_PATH`
- **THEN** используется эта команда, даже если пакет `sdo_mcp` установлен

#### Scenario: Установленный пакет
- **WHEN** `SDO_MCP_SERVER_PATH` не задан и пакет `sdo_mcp` найден
- **THEN** сервер запускается как `process.execPath` с аргументом `<пакет>/dist/index.js` и переменной `ELECTRON_RUN_AS_NODE=1`

#### Scenario: Путь внутри asar
- **WHEN** найденный путь пакета проходит через `app.asar`
- **THEN** точка входа берётся из `app.asar.unpacked`

### Requirement: Браузер без отдельной загрузки на Windows

Десктопное приложение на Windows SHALL передавать серверу `SDO_BROWSER_CHANNEL=msedge`, если пользователь не задал переменную сам.

#### Scenario: Канал по умолчанию
- **WHEN** приложение запускает SDO MCP на Windows без `SDO_BROWSER_CHANNEL` в окружении
- **THEN** сервер получает `SDO_BROWSER_CHANNEL=msedge`

### Requirement: Классификация ошибок запуска

MCP-клиент SHALL при неудачном подключении сообщать причину `not_found`, `exited` или `timeout` вместе с источником команды и редактированным хвостом stderr; ошибки инструментов MUST NOT считаться недоступностью сервера.

#### Scenario: Команда не найдена
- **WHEN** исполняемый файл сервера отсутствует
- **THEN** клиент сообщает причину `not_found`

#### Scenario: Сервер завершился
- **WHEN** процесс сервера завершается до ответа на рукопожатие
- **THEN** клиент сообщает причину `exited` и хвост stderr без секретов

#### Scenario: Нет ответа
- **WHEN** рукопожатие не завершается за `connectionTimeout`
- **THEN** клиент закрывает транспорт и сообщает причину `timeout`

### Requirement: Сообщение о недоступности SDO MCP

Онбординг SHALL при недоступности SDO MCP переходить в фазу `failed` с сообщением, объясняющим причину, вместо формы входа.

#### Scenario: Компонент не найден
- **WHEN** проверка сессии или вход завершается ошибкой `not_found`
- **THEN** пользователь видит «Компонент входа SDO MCP не найден. Переустановите приложение.» и кнопку «Повторить»

#### Scenario: Компонент не запустился
- **WHEN** проверка сессии или вход завершается ошибкой `exited` или `timeout`
- **THEN** пользователь видит сообщение о том, что компонент не запустился, с путём к журналу

#### Scenario: Прочие ошибки
- **WHEN** проверка сессии завершается ошибкой, не связанной с запуском сервера
- **THEN** онбординг показывает форму входа с сообщением, как раньше

### Requirement: Журнал ядра без секретов

Ядро SHALL записывать выбранный источник сервера и ошибки запуска SDO MCP в `logs/core.log`; записи MUST проходить редакцию секретов, а окружение сервера MUST NOT записываться.

#### Scenario: Ошибка запуска в журнале
- **WHEN** SDO MCP не запускается
- **THEN** в `core.log` появляется запись с причиной, источником и редактированным хвостом stderr

#### Scenario: Ротация
- **WHEN** `core.log` превышает 1 МБ
- **THEN** файл переименовывается в `core.log.1`, и запись продолжается в новый `core.log`

#### Scenario: Сбой записи журнала
- **WHEN** запись в журнал невозможна
- **THEN** ядро продолжает работу без исключения
