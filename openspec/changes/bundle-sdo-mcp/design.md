# Design

## Context

Полный согласованный дизайн и обоснование: [2026-10-13-bundled-sdo-mcp-design.md](../../../docs/superpowers/specs/2026-10-13-bundled-sdo-mcp-design.md). Поведенческие контракты — в `specs/sdo-mcp-runtime`.

## Goals / Non-Goals

**Goals:**

- sdo_mcp ставится через `npm install` и запускается без установленного Node.js и ручной настройки путей.
- При неудачном запуске пользователь видит понятную причину, а подробности пишутся в локальный журнал без секретов.

**Non-Goals:**

- Настройка `electron-builder` и сборка установщика (фаза 4).
- Выбор папки sdo_mcp в интерфейсе (заменён зависимостью; для разработки остаётся `SDO_MCP_SERVER_PATH`).
- Повторный вход с сохранённым паролем, распознавание неверного пароля и ручной вход при капче.

## Decisions

### Поставка как git-зависимость, а не выбор папки

Пакет из `github:tab11pm/sdo-mcp#v1.2.0` попадает в `node_modules` и в будущий установщик без действий пользователя. Альтернативы — выбор папки с ручной сборкой или кнопка «Подготовить» с системным npm — требуют Node.js, интернета и разбора ошибок npm от нетехнического пользователя.

### Node из Electron

Сервер запускается как `process.execPath` + `dist/index.js` с `ELECTRON_RUN_AS_NODE=1`. В CLI `process.execPath` — обычный `node`, поэтому один код работает в обоих режимах.

### Edge вместо скачиваемого Chromium

`SDO_BROWSER_CHANNEL=msedge` на Windows убирает загрузку около 150 МБ браузера Playwright.

### Ошибки без новой фазы онбординга

Недоступность SDO MCP переводит онбординг в существующую фазу `failed` с текстом по причине; прочие ошибки сохраняют прежнее поведение.

## Risks / Trade-offs

- `prepare` скачивает devDependencies sdo_mcp при `npm install` → приемлемо для разработки; установщик собирается заранее.
- Node в Electron может отстать от требований sdo_mcp → обновлять Electron вместе с sdo_mcp.
- На Windows без Edge вход упадёт при запуске браузера → ошибка попадает в журнал; обход — пустой `SDO_BROWSER_CHANNEL` и ручная установка Chromium.
