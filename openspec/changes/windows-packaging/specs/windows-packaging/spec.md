# Windows Packaging Specification

## Purpose

Проверяемая поставка существующего desktop-приложения одним Windows-установщиком, без изменения политики Edge/Chromium и без внешних developer-зависимостей у пользователя.

## ADDED Requirements

### Requirement: Самодостаточный установщик

Приложение SHALL поставляться Windows x64 NSIS-установщиком для текущего пользователя. Runtime Electron/Node, приложение, production-зависимости, SDO MCP, Playwright CLI и Electron-native SQLite SHALL находиться в пакете. Chromium MUST NOT включаться в установщик; по умолчанию SHALL использоваться Edge.

#### Scenario: Чистая Windows

- **WHEN** пользователь устанавливает приложение без системных Node.js/npm и исходного репозитория
- **THEN** приложение запускается, а Chromium при необходимости устанавливается только по явному действию внутри UI

### Requirement: Установка и удаление только для текущего пользователя

Установщик MUST устанавливать приложение только для текущего пользователя и не запрашивать повышение прав. При явном `/allusers` установщик и деинсталлятор SHALL завершаться с ненулевым кодом до запуска секций установки или удаления, без UAC и без изменения файлов приложения или его регистрационных записей. Предварительная инициализация шаблона может настроить путь, включить журналирование или проверить запущенное приложение до проверки `/allusers`.

#### Scenario: Запуск установщика с повышенными правами

- **WHEN** пользователь запускает установщик интерактивно или без интерфейса, в том числе уже с правами администратора
- **THEN** приложение устанавливается только в контекст текущего пользователя и установщик не запрашивает повышение прав

#### Scenario: Явный запрос установки для всех пользователей

- **WHEN** установщик или деинсталлятор запускается с `/allusers`, в том числе без интерфейса
- **THEN** он завершается с ненулевым кодом без запроса повышения прав, без запуска секций установки или удаления и без изменения файлов приложения или его регистрационных записей

### Requirement: Исполняемые runtime-ресурсы

SDO MCP, Playwright CLI и их runtime-зависимости SHALL быть доступны вне ASAR; native SQLite SHALL соответствовать Windows x64 и текущей версии Electron. Сборка MUST отклонять отсутствующий или неверный native-ресурс до выдачи артефакта.

#### Scenario: Чужая native-сборка

- **WHEN** упаковке передан Linux-бинарник или stamp другой версии Electron/архитектуры
- **THEN** сборка завершается ненулевым кодом, не выдавая такой пакет за пригодный установщик

#### Scenario: Путь с пробелами и кириллицей

- **WHEN** приложение установлено в такой путь и запускает bundled MCP или CLI Playwright
- **THEN** процесс запускается без shell и без поиска системного Node.js

### Requirement: Изоляция packaged-конфигурации

Packaged main, worker и bundled MCP MUST NOT загружать `.env` из cwd, каталога приложения или workspace. Developer-режим SHALL сохранять существующую поддержку `.env`.

#### Scenario: Подложный `.env`

- **WHEN** packaged-приложение запускается из каталога с `.env`, содержащим sentinel-настройки/учётные данные
- **THEN** main и MCP не загружают их, а stdout дочернего MCP остаётся протокольным

### Requirement: Сохранение приватных данных

Пакет MUST NOT включать пользовательские сессии, базы, профили, логи, `.env` или диагностические архивы. Обновление и удаление приложения SHALL сохранять данные `%LOCALAPPDATA%/OnlineLecture` и общий browser cache. Uninstaller SHALL удалять только собственные ярлыки и собственную регистрацию автозапуска.

#### Scenario: Переустановка после удаления

- **WHEN** пользователь удаляет программу без отдельной очистки аккаунта и устанавливает её снова
- **THEN** локальная база и настройки остаются доступны, а браузерный кэш не удаляется

### Requirement: Единственный экземпляр и идентичность Windows

Приложение SHALL использовать стабильный `appId=ru.onlinelecture.desktop` для установщика и Windows-уведомлений. Второй экземпляр MUST NOT запускать второй worker/планировщик и SHALL открывать существующее окно. Автозапуск MUST NOT включаться без явного выбора пользователя.

#### Scenario: Повторный запуск

- **WHEN** пользователь снова запускает установленный exe при работающем приложении
- **THEN** открывается существующее окно и второй планировщик не создаётся

### Requirement: Доказательная проверка поставки

Проверка SHALL включать состав реально созданного пакета, packaged fake-session E2E и отдельный Windows smoke без developer-инструментов. Linux-результаты MUST NOT обозначаться как пройденная Windows-проверка. Сборка SHALL отключать публикацию; неподписанный тестовый артефакт MUST NOT называться подписанным публичным релизом.

#### Scenario: Доступен только Linux

- **WHEN** unit-тесты и проверки конфигурации проходят, но установщик не запускался на Windows
- **THEN** handoff явно оставляет Windows-проверки незакрытыми
