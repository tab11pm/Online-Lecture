# Spec Delta

## Purpose

Определяет авторизованный импорт онлайн-пар группы из расписания ТУСУР, их сопоставление с курсами SDO и безопасное слияние с сохранённым расписанием.

## ADDED Requirements

### Requirement: Определение группы

`TimetableClient` SHALL по авторизованной главной `timetable.tusur.ru` находить ссылку
«Мое расписание» и извлекать из неё факультет и группу.

#### Scenario: Ссылка найдена
- **WHEN** авторизованная главная содержит ссылку вида `/faculties/<faculty>/groups/<group>`
- **THEN** клиент возвращает факультет и группу

#### Scenario: Ссылка не найдена
- **WHEN** на главной нет ссылки «Мое расписание»
- **THEN** клиент завершается ошибкой и предлагает добавить пару вручную

### Requirement: Сбор онлайн-пар группы

Клиент SHALL собирать пары по неделям и оставлять только пары с признаком «реализуется в ЭИОС»,
дедуплицируя их по `lessonId`.

#### Scenario: Пометка ЭИОС
- **WHEN** в блоке пары присутствует заметка «реализуется в ЭИОС»
- **THEN** пара считается онлайн и попадает в результат

#### Scenario: Полное имя дисциплины
- **WHEN** парсер извлекает дисциплину
- **THEN** он использует полное имя из `title`, а не аббревиатуру `abbr`

### Requirement: Сопоставление дисциплины с курсом SDO

Импортёр SHALL для онлайн-дисциплин запрашивать `course_links` и извлекать `sdoCourseId` из URL.

#### Scenario: Ссылка на курс найдена
- **WHEN** `course_links` содержит `https://sdo.tusur.ru/auth/edu?id=<id>`
- **THEN** дисциплина сопоставляется с курсом SDO `<id>`

#### Scenario: Ссылка отсутствует
- **WHEN** `course_links` пуст или не содержит id
- **THEN** занятия попадают в список несопоставленных и не создают заданий

### Requirement: Резолв BBB через SDO MCP

Импортёр SHALL вызывать `resolve_online_lecture` для курса SDO и обрабатывать все статусы резолва.

#### Scenario: Однозначный резолв
- **WHEN** MCP возвращает `resolved`
- **THEN** задание получает точный URL BBB-активности (`target.type = 'direct'`)

#### Scenario: Неоднозначный резолв
- **WHEN** MCP возвращает `ambiguous`
- **THEN** пользователь выбирает точную активность до сохранения задания

#### Scenario: Не найдено
- **WHEN** MCP возвращает `not_found`
- **THEN** дисциплина пропускается и пользователь получает уведомление

#### Scenario: Требуется авторизация
- **WHEN** MCP возвращает `auth_required`
- **THEN** импорт останавливается и предлагает повторный вход

### Requirement: Построение импортированных заданий

Импортёр SHALL строить задания `source: 'timetable'` из онлайн-пар: id
`tt:<faculty>:<group>:<sdoCourseId>`, `origin`, цель и расписание `imported` по датам.

#### Scenario: Задание из онлайн-дисциплины
- **WHEN** дисциплина успешно сопоставлена и разрешена
- **THEN** создаётся одно авто-задание со всеми онлайн-парами в виде вхождений `{date, joinAt, leaveAt}`

### Requirement: Слияние при обновлении

Обновление расписания SHALL сливать пришедшие онлайн-пары с сохранёнными, не изменяя ручные
задания и сохраняя правки и скрытые вхождения.

#### Scenario: Новые и исчезнувшие даты
- **WHEN** обновление приносит новую дату и больше не содержит старую
- **THEN** новая дата добавляется, а старая неотредактированная удаляется

#### Scenario: Ручное задание
- **WHEN** обновление затрагивает задание со `source: 'manual'`
- **THEN** задание не изменяется

#### Scenario: Ошибка импорта
- **WHEN** сеть или разметка недоступны во время обновления
- **THEN** сохранённое расписание не изменяется и пользователь получает «Повторить»

### Requirement: Команда CLI `import`

CLI SHALL предоставлять команду `import --db <path>` для ручного smoke-импорта, сохраняющую
базу только после успешной сборки и слияния.

#### Scenario: Успешный импорт
- **WHEN** команда `import` выполняется с доступной авторизацией и фикстурами
- **THEN** авто-задания сохраняются в базе и выводится сводка

#### Scenario: Ошибка сети
- **WHEN** выборка расписания завершается ошибкой
- **THEN** команда завершается с ненулевым кодом и не изменяет базу
