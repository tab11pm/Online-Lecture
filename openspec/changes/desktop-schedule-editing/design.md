# Design

Полный архитектурный дизайн: [Редактирование расписания в десктопе](../../../docs/superpowers/specs/2026-10-18-desktop-schedule-editing-design.md).

## Decisions

- Пользовательские исправления хранятся в существующей модели `Job`/`ImportedOccurrence`.
- Перенос выполняется одной транзакцией: `suppressed` у исходного вхождения и связанная ручная `once`.
- Команды редактирования и импорт сериализуются в worker; сетевой поиск через MCP выполняется вне транзакции.
- Renderer видит названия и непрозрачные ID кандидатов, но не внутренние URL активностей.

## Risks

- `occurrenceId` включает время входа: правка разрешена только до запуска, чтобы новый ID не вызвал повторный вход.
- Повторный импорт может прийти во время ручной правки: merge перечитывает актуальные задания после захвата общей очереди записи.
- Неоднозначный результат MCP требует явного выбора активности до сохранения.
