# Online Lecture для SDO ТУСУР

## 1. Назначение

Online Lecture — локальное приложение для Windows 10/11, которое помогает одному студенту автоматически подключаться к онлайн-лекциям ТУСУР по расписанию и корректно покидать их.

Приложение должно:

- запускаться вместе с Windows и продолжать работу в системном трее;
- автоматически находить группу студента и импортировать онлайн-пары из расписания `timetable.tusur.ru`;
- находить точную ссылку на лекцию через существующий SDO MCP либо использовать заранее указанную Moodle-ссылку;
- входить в BigBlueButton в заданное время в режиме «только слушать»;
- всегда оставлять камеру и микрофон выключенными;
- выходить при завершении встречи организатором либо в заданное время;
- показывать системные уведомления и историю запусков;
- устанавливаться одним Windows-установщиком без ручной установки Node.js, Playwright, MCP, SQLite и других зависимостей.

Продукт рассчитан в том числе на пользователей, которые умеют только устанавливать обычные Windows-программы и работать с браузером. Терминал, YAML, MCP и база данных не должны быть видимы в пользовательском сценарии.

## 2. Границы первой версии

Первая версия поддерживает:

- одного локального пользователя и один аккаунт ТУСУР;
- Windows 10/11;
- SDO ТУСУР и BigBlueButton на `bbb2.tusur.ru`;
- автоимпорт онлайн-пар из расписания ТУСУР;
- разовые и еженедельные расписания;
- вход по точной Moodle-ссылке либо через поиск курса и лекции;
- видимый браузер как основной режим: Edge по умолчанию на Windows, Chromium по выбору пользователя;
- экспериментальный headless-режим без гарантии работы WebRTC и аудио;
- локальные desktop-уведомления и журнал запусков.

В первую версию не входят:

- облачный сервис и хранение университетских сессий на сервере;
- несколько пользователей или аккаунтов;
- Telegram-уведомления;
- импорт произвольных календарей и сложные cron-расписания;
- установщики для Linux и macOS;
- Zoom, SberJazz и другие конференц-платформы;
- пробуждение компьютера из сна;
- запуск на выключенном компьютере;
- обход удаления или запрета входа со стороны модератора.

Использование автоматического присутствия должно соответствовать правилам учебного заведения.

## 3. Архитектура

```text
Electron UI
    |
    v
Локальное ядро и планировщик
    |
    +---- stdio MCP ----> SDO MCP ----> profile.tusur.ru / sdo.tusur.ru
    |
    +---- HTTPS --------> timetable.tusur.ru (авторизованный импорт расписания)
    |
    +---- Playwright ----> Moodle BBB activity ----> bbb2.tusur.ru
```

### 3.1 Разделение ответственности

SDO MCP отвечает только за:

- проверку авторизации в SDO;
- получение курсов;
- поиск BBB-активности внутри курса;
- возврат стабильной Moodle-ссылки на лекцию;
- обновление сохранённой SDO-сессии.

Новое приложение отвечает за:

- расписание;
- импорт онлайн-пар из `timetable.tusur.ru` и его обновление;
- хранение заданий и истории;
- запуск SDO MCP через `stdio`;
- долгоживущий Playwright-сеанс лекции;
- подключение к аудио в режиме слушателя;
- контроль состояния BBB;
- повторное подключение при техническом сбое;
- своевременный выход;
- UI, трей и уведомления.

MCP-вызов не должен оставаться открытым на протяжении лекции. SDO MCP кратковременно разрешает ссылку, после чего приложение самостоятельно управляет BBB-сеансом.

### 3.2 Почему не обычный web-app

Обычная веб-страница не может надёжно:

- управлять интерфейсом `sdo.tusur.ru` и `bbb2.tusur.ru` из-за политики same-origin;
- продолжать работу после закрытия вкладки;
- запускать браузер по расписанию;
- использовать университетскую сессию без передачи её удалённому серверу.

Electron предоставляет web-интерфейс, но работает как локальное Windows-приложение с фоновым процессом и встроенными зависимостями.

## 4. Этапы реализации

### 4.1 Этап A — ядро и технический CLI

На первом этапе создаётся проверяемое ядро автоматизации и временный CLI для разработки.

CLI поддерживает команды:

- `config validate` — проверить технический YAML-конфиг;
- `auth check` — проверить сессию ТУСУР;
- `jobs list` — показать задания;
- `run` — запустить планировщик;
- `run-once <job-id>` — немедленно проверить одно задание, сохраняя установленное время выхода.

Технический YAML поддерживает две цели:

```yaml
id: math-monday
enabled: true
schedule:
  type: weekly
  days: [mon]
  joinAt: "10:00"
  leaveAt: "11:35"
  timezone: Asia/Krasnoyarsk
target:
  type: search
  course: "Математика"
  lecture: "Онлайн-лекция"
browser:
  headless: false
```

Вместо поиска разрешается `target.type: url` с точным URL Moodle BBB-активности. Базовый адрес `https://bbb2.tusur.ru/html5client/` не является ссылкой конкретной встречи и должен отклоняться.

### 4.2 Этап B — Windows-приложение

После проверки ядра создаётся Electron-приложение с React/TypeScript UI и Windows-установщиком.

Установщик включает:

- Electron/Node runtime;
- приложение и локальное ядро;
- собранный SDO MCP;
- Playwright, включая CLI для установки управляемого Chromium из приложения;
- встроенную SQLite-библиотеку;
- необходимые native-модули и ресурсы.

Пользователь не устанавливает зависимости вручную.

Chromium в установщик не включается. На Windows по умолчанию используется установленный Edge. Пользователь может выбрать Chromium и загрузить его кнопкой «Установить Chromium» внутри приложения, без системных Node.js, npm или терминала. Загрузка начинается только по явному действию пользователя.

Выбор браузера сохраняется и применяется к новым операциям входа через SDO MCP, импорта расписания и открытия BBB. Рабочая браузерная сессия при смене выбора не прерывается. Доступность Chromium подтверждается наличием основного браузера и headless shell для текущей версии Playwright; до успешной установки прежний выбор сохраняется. При ошибке загрузки показываются причина и повторная попытка, повторное нажатие во время установки не запускает второй процесс. Если браузер отсутствует или после обновления Playwright требуется другая версия, приложение снова предлагает установку.

CLI Playwright, SDO MCP и их необходимые runtime-зависимости должны быть доступны вне `app.asar`, чтобы дочерние процессы запускались через встроенный Node Electron. Актуальная политика выбора и установки браузера: `openspec/changes/chromium-choice-install/` (уточнение пользователя от 2026-10-19; прежнее требование включать Chromium в установщик устарело).

## 5. Интеграция с SDO MCP

Существующий SDO MCP расширяется поддержкой типа модуля BBB:

```text
/mod/bigbluebuttonbn/view.php
```

Добавляется tool:

```ts
resolve_online_lecture({
  courseUrl?: string,
  courseQuery?: string,
  lectureQuery?: string
}) =>
  | { status: "resolved"; course: CourseRef; module: BbbModuleRef }
  | { status: "ambiguous"; candidates: BbbModuleRef[] }
  | { status: "not_found"; candidates: [] }
  | { status: "auth_required" }
```

Правила контракта:

- передаётся ровно один из `courseUrl` или `courseQuery`;
- `lectureQuery` необязателен;
- при единственной однозначной BBB-активности возвращается `resolved`;
- при нескольких допустимых совпадениях возвращается `ambiguous`;
- приложение никогда не выбирает первый похожий результат автоматически;
- наружу возвращается Moodle URL, но не временный BBB `sessionToken`;
- путь к общей авторизационной сессии задаётся через `SDO_AUTH_STATE_PATH`;
- packaged-режим не читает логин и пароль из `.env`;
- при истёкшей сессии возвращается `auth_required`;
- существующие MCP tools сохраняют обратную совместимость;
- Playwright browser/context всегда корректно закрываются и не оставляют фоновые Chromium-процессы.

При доработке SDO MCP необходимо сохранить существующие незакоммиченные пользовательские изменения.

## 6. Расписание и автомат состояний

Каждый запуск идентифицируется парой:

```text
jobId + occurrenceId
```

Повторный запуск одного occurrence запрещён.

Основные состояния:

```text
scheduled
  -> resolving
  -> joining
  -> waiting_room
  -> connected
  -> reconnecting
  -> leaving
  -> completed
```

Терминальные состояния ошибок:

- `skipped` — временное окно уже завершилось;
- `blocked` — неоднозначный поиск, истёкшая сессия или запрет модератора;
- `failed` — исчерпаны технические попытки.

Правила:

- если приложение запущено после `joinAt`, но до `leaveAt`, оно немедленно пытается войти;
- после `leaveAt` вход не выполняется;
- если преподаватель ещё не запустил комнату, приложение остаётся в `waiting_room` до входа или `leaveAt`;
- открытая страница ожидания не считается успешным присутствием;
- `connected` устанавливается только после подтверждения входа в BBB-клиент;
- сетевой разрыв вызывает не более трёх повторов через 5, 15 и 30 секунд;
- явное удаление модератором не вызывает повторный вход;
- `leaveAt` является жёстким пределом;
- SIGINT, SIGTERM и ручная остановка корректно закрывают BBB-сеанс;
- причина завершения сохраняется как `meeting_ended`, `deadline`, `manual` или `error`.

## 7. Пользовательский интерфейс

### 7.1 Первый запуск

Onboarding состоит из этапов:

1. Приветствие и вход: логин (или почта) и пароль на форме приложения, затем SSO `profile.tusur.ru`.
2. Если сохранённая сессия уже валидна, шаг входа пропускается; при капче или 2FA открывается видимое окно ТУСУР.
3. Авто-импорт с прогрессом: поиск группы, онлайн-пары, сопоставление с курсами SDO и BBB-активностью.
4. Результат: список найденных онлайн-пар с действиями «Подключить», «Отредактировать», «Пропустить».
5. Готово: приложение работает в трее, автозапуск включается явно.

Логин и пароль хранятся только локально; пароль — в зашифрованном виде (DPAPI на Windows). Сохраняется также локальная браузерная сессия `.tusur.ru`, общая для SDO и timetable.

### 7.2 Главное окно

Главный экран показывает:

- ближайшую лекцию;
- состояние фоновой работы;
- список расписаний;
- статус последнего запуска;
- кнопку добавления лекции;
- кнопку проверки входа;
- кнопку ручной остановки активной лекции;
- переход к журналу.

Поиск лекции, подключение, ожидание преподавателя, восстановление соединения и выход отображаются как разные состояния. До подтверждения подключения интерфейс не сообщает, что лекция уже идёт или приложение слушает её. Прогресс импорта различает завершённые, текущий и предстоящие этапы; при ошибке остаются видны время последнего успешного обновления и действие повтора.

### 7.3 Мастер добавления

Последовательность:

```text
Ссылка или поиск курса
    -> выбор и подтверждение найденной BBB-активности рядом с результатами поиска
    -> «разово» (конкретная дата) или «каждую неделю» (дни недели)
    -> время входа и выхода, название пары
    -> сохранение
```

Если найдено несколько вариантов, пользователь выбирает точную активность до сохранения задания.

Дата в формах отображается в формате `ДД.ММ.ГГГГ`, время — `ЧЧ:ММ` (24 часа), независимо от локали браузера. Внутренние форматы расписания не меняются. Модальные формы поддерживают управление с клавиатуры, а панель сохранения остаётся видимой при прокрутке.

Для конкретной пары доступно действие «Перенести»: исходное вхождение скрывается, а на новое время создаётся связанная разовая пара. Удаление авто-пары скрывает её (обновление расписания не вернёт пару), удаление ручной пары удаляет её окончательно.

### 7.4 Фоновая работа

- Закрытие главного окна скрывает его, но не завершает приложение.
- Трей показывает текущий статус и позволяет открыть окно, остановить активную лекцию или полностью выйти.
- Автозапуск вместе с Windows включается явно в onboarding и изменяется в настройках.
- Приложение не управляет режимом сна Windows.
- После пробуждения оно входит только в том случае, если временное окно лекции ещё активно.

## 8. Локальное хранилище

Расписание, история и защита от двойного запуска хранятся во встроенной SQLite-базе в `%LOCALAPPDATA%`.

Расписание поддерживает три вида вхождений: `once` (разовая пара), `weekly` (еженедельная) и `imported` (импортированные онлайн-пары по датам). Импортированные вхождения имеют флаги `edited` (пользователь правил — обновление не перезатирает) и `suppressed` (пользователь выключил — обновление не возвращает). Задание имеет источник `source` (`manual` или `timetable`); задания без `source` считаются ручными.

SQLite:

- поставляется внутри приложения;
- не требует отдельной установки;
- не показывается пользователю;
- используется для атомарных переходов состояний и защиты от дублей;
- в будущем используется тем же Electron UI без отдельного сервера.

Приложение должно:

- автоматически создавать базу при первом запуске;
- выполнять версионированные миграции;
- регулярно создавать локальную резервную копию расписания;
- при повреждении базы не перезаписывать её молча;
- перемещать повреждённый файл в диагностическую копию;
- попытаться восстановить расписание из последней резервной копии;
- сообщить пользователю о результате восстановления;
- создать пустую базу только при отсутствии пригодной резервной копии.

## 9. Безопасность и приватность

- Браузерная сессия, база и логи хранятся только в `%LOCALAPPDATA%` текущего пользователя Windows.
- Логин и пароль хранятся только локально; пароль шифруется (DPAPI на Windows) и никогда не передаётся на сервер.
- Телеметрия и удалённый сервер отсутствуют.
- Автоматизация разрешает только HTTPS и allowlist доменов ТУСУР, SDO и BBB.
- Cookies, query-параметры, join URL и `sessionToken` вырезаются из логов и уведомлений.
- Диагностический архив создаётся только по явному действию пользователя и также проходит redaction.
- Удаление аккаунта из приложения после подтверждения удаляет браузерную сессию и локальное расписание.
- Electron renderer запускается с `nodeIntegration: false` и `contextIsolation: true`.
- Доступ к расписанию, базе и браузеру идёт только через узкий типизированный IPC.
- Видимый браузер является режимом по умолчанию и позволяет пользователю вмешаться при неожиданном экране; на Windows используется Edge, если пользователь не выбрал Chromium.

## 10. Уведомления и журнал

Системные уведомления показываются при:

- успешном входе;
- выходе из лекции;
- необходимости повторной авторизации;
- неоднозначном поиске;
- технической ошибке;
- исчерпании повторных попыток.

Логи:

- структурированы по `jobId` и `occurrenceId`;
- имеют ограниченную ротацию;
- не содержат секретных URL и сессионных данных;
- отображаются в UI понятными пользовательскими сообщениями.

Журнал различает пустую историю и отсутствие ошибок в выбранном фильтре. Ошибка загрузки следующей страницы не скрывает ранее загруженные записи; повтор загружает ту же страницу, а смена фильтра сбрасывает состояние загрузки и игнорирует устаревшие ответы.

## 11. Проверки и критерии приёмки

### 11.1 Unit-тесты

- разовые и еженедельные задания;
- явные часовые пояса;
- поздний старт;
- жёсткий `leaveAt`;
- защита от повторного occurrence;
- переходы автомата состояний;
- политика повторов 5/15/30 секунд;
- redaction секретных данных;
- резервное копирование и восстановление SQLite.

### 11.2 Контрактные тесты SDO MCP

- единственное совпадение;
- несколько кандидатов;
- отсутствие BBB-модуля;
- истёкшая сессия;
- неподдерживаемый URL;
- распознавание `/mod/bigbluebuttonbn/view.php`;
- закрытие browser/context после каждого tool-вызова.

### 11.3 Fixture E2E BBB

- ожидание модератора;
- успешный listen-only вход;
- камера и микрофон остаются выключенными;
- завершение встречи организатором;
- выход по времени;
- сетевой разрыв и успешное переподключение;
- исчерпание повторов;
- удаление модератором без повторного входа;
- ручная остановка.

### 11.4 Windows E2E

На чистой Windows-машине проверяются:

- установка одним файлом;
- отсутствие необходимости вручную устанавливать Node.js, npm, Playwright, MCP или SQLite;
- работа с Edge по умолчанию без загрузки Chromium;
- установка Chromium кнопкой по явному действию пользователя без системных Node.js и npm, повтор после ошибки и единое применение выбора к SDO MCP, импорту и BBB;
- onboarding;
- вход через ТУСУР с локальным зашифрованным хранением пароля;
- автозапуск;
- работа в трее;
- desktop-уведомления;
- восстановление после перезапуска;
- удаление приложения.

Реальный smoke-тест с ТУСУР выполняется вручную и только на тестовой или разрешённой лекции.

### 11.5 Автоимпорт расписания

- определение группы по авторизованной главной `timetable.tusur.ru`;
- извлечение полного имени дисциплины, а не аббревиатуры `abbr`;
- детект онлайн-пар по признаку «реализуется в ЭИОС»;
- сопоставление дисциплины с курсом SDO через `course_links` и резолв BBB-активности;
- слияние при обновлении: новые даты добавляются, исчезнувшие удаляются, `edited` сохраняется, `suppressed` не возвращается;
- ручные пары `manual` не изменяются обновлением;
- дедупликация ручной и авто-пары по (дата, время, дисциплина) — один вход;
- «разово» срабатывает один раз, «каждую неделю» повторяется, «Перенести» скрывает исходное вхождение и создаёт разовую пару;
- обезличенные фикстуры недель, `course_links` и статусов MCP; миграция старых заданий без `source` в `manual`.

## 12. Критерий пользовательского успеха

Нетехнический пользователь должен суметь:

1. Скачать и установить приложение.
2. Войти через обычную страницу ТУСУР.
3. Добавить лекцию по ссылке или названию курса.
4. Выбрать дату и время.
5. Закрыть главное окно, оставив приложение в трее.
6. Получить подтверждённый автоматический вход и выход без терминала и установки дополнительных программ.
