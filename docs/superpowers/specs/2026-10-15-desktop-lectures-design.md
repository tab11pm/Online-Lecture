# Автопосещение лекций в десктопном приложении (slice 2a) — дизайн

**Дата:** 2026-10-15  
**Статус:** на ревью  
**OpenSpec:** `openspec/changes/desktop-lectures`

## Цель

После входа приложение само находит онлайн-пары студента в `timetable.tusur.ru`, показывает их и в фоне заходит на каждую лекцию BBB от `joinAt` до `leaveAt`. Пользователь видит, что идёт сейчас и что будет дальше, может остановить активную лекцию из окна или трея и пропустить отдельную пару.

## Границы

Входит:

- автоимпорт расписания после входа, при запуске (если прошло больше 24 ч), раз в сутки и по кнопке, с прогрессом по стадиям;
- главное окно: текущая и ближайшая лекция, список пар на 14 дней, итог последнего импорта, нераспознанные дисциплины;
- фоновый планировщик в процессе ядра и запуск лекций через `JobRunner` с жизненным циклом из `real-run-lifecycle`;
- «Остановить» активную лекцию из окна и трея; «Пропустить»/«Вернуть» для одного вхождения;
- настройка «Показывать окно лекции» (видимый или скрытый браузер BBB);
- реакция на сон и пробуждение ОС, на истёкшую сессию и на выход из приложения во время лекции.

Не входит (slice 2b и позже): правка времени пары, «Перенести», мастер ручной пары, уведомления Windows и журнал (slice 3), упаковка (фаза 4).

## Текущее состояние

- Worker (`apps/desktop/src/worker`) выполняет только onboarding: вход через `sdo_mcp`, проверку сессии, выбор браузера.
- Ядро уже умеет: импорт (`src/timetable/`, CLI `import`), слияние с сохранением `edited`/`suppressed` и удалением только при полном импорте, `Scheduler.check()`, `JobRunner.runJob(jobId, occurrenceId, signal)` с жёстким `leaveAt`, повторами и отменой.
- Конвейер импорта собран прямо в `src/cli/commands.ts`; записи заданий выполняются по одной, без транзакции.

## Решение

### Архитектура: всё состояние в процессе ядра

Планировщик, импорт, SQLite и активные запуски живут в worker (utility-процесс ядра). Main пересылает команды и события, держит трей, `powerMonitor` и настройки. Renderer получает снимок состояния и подписывается на изменения. Ядро в `src/` не зависит от Electron.

Отклонённые варианты: планировщик в main (состояние делится между процессами, оба пишут в SQLite) и отдельный CLI-демон (второй жизненный цикл процесса, свой IPC, сложности автозапуска и упаковки).

### Ядро (`src/`)

- `src/timetable/import-service.ts` — `runTimetableImport(deps, options)`: конвейер, вынесенный из CLI. Зависимости: фетчер, резолвер, репозиторий заданий, часы. Опция `onProgress(stage)`, где стадии: `group`, `schedule`, `courses`, `lectures`, `saving`. Результат:
  - `completed` — группа, сводка merge, `unresolved` (дисциплины без лекции BBB в СДО), `ambiguous`, `unmapped` (пары без ссылки на курс) и признак `complete`;
  - `auth_required` — база не изменена;
  - `failed` — сообщение после `redactSensitiveText`, база не изменена.
  
  Найденные пары сохраняются и при частичном результате; удаление (`prune`) выполняется только при полном импорте. Это текущее правило CLI, оно сохраняется. Запись результата выполняется одной транзакцией SQLite. CLI `import` переходит на этот сервис без изменения вывода и кодов выхода.
- `src/persistence/job-repository.ts` — атомарная замена заданий расписания одной транзакцией.
- `src/core/lecture-agenda.ts` — чистая функция `buildAgenda(jobs, runs, now, days)`: вхождения на `days` дней вперёд с учётом `suppressed`, текущая и ближайшая лекция, последний завершённый запуск.

### Worker (`apps/desktop/src/worker`)

- `LectureService` открывает `data/lectures.db`, владеет `SchedulerLoop`, `ImportScheduler` и активным запуском, строит `LecturesView` и публикует `lectures.changed` при каждом изменении.
- `SchedulerLoop` вызывает `Scheduler.check(now)` каждые 30 секунд и сразу после `system.resumed`. Его `LectureRunner` запускает `JobRunner.runJob(jobId, occurrenceId, signal)` с отдельным `AbortController`. Параметры браузера берутся из настроек: `channel` по выбору браузера, `headless` по настройке окна. Одновременно выполняется не больше одной лекции. Если окна пар пересекаются, вторая ждёт и входит, только пока её окно активно.
- `ImportScheduler` запускает импорт после перехода онбординга в `session_ready`, при старте, если последний успешный импорт старше 24 часов, раз в сутки и по команде. Во время активной лекции автоматический импорт откладывается до её завершения. После неудачи автоповтор не чаще раза в час. Время последнего успешного импорта хранится в SQLite. Повторная команда во время импорта не запускает второй.
- Импорт и планировщик работают только в состоянии `session_ready`. Результат `auth_required` из импорта или резолва лекции переводит онбординг в «Войдите снова» и останавливает планировщик до следующего `session_ready`.
- При старте worker запуски в промежуточных статусах (`resolving`, `joining`, `waiting_room`, `connected`, `reconnecting`, `leaving`) помечаются `failed` с причиной `error`: процесс, который их вёл, больше не существует. Повторного входа в то же вхождение нет, потому что SPEC запрещает повторный запуск одного occurrence. Это осознанное ограничение slice 2a.

### Протокол

Снимок для UI (`apps/desktop/src/shared/lectures.ts`) передаётся целиком при каждом изменении:

```ts
interface LecturesView {
  current?: { jobId: string; occurrenceId: string; title: string; leaveAt: string; status: RunStatus };
  next?: AgendaItem;
  agenda: AgendaItem[];
  import: ImportView;
  lastRun?: { title: string; status: RunStatus; completionReason?: CompletionReason; at: string };
}

interface AgendaItem {
  jobId: string;
  occurrenceId: string;
  title: string;
  date: string;
  joinAt: string;
  leaveAt: string;
  skipped: boolean;
  runStatus?: RunStatus;
}

type ImportView =
  | { status: 'idle'; lastSuccessAt?: string }
  | { status: 'running'; stage: ImportStage; lastSuccessAt?: string }
  | { status: 'done'; at: string; summary: ImportSummaryView; unresolved: string[] }
  | { status: 'failed'; at: string; message: string; lastSuccessAt?: string };
```

`title` — полное имя дисциплины из `origin.discipline`. В снимке нет URL курсов и активностей, cookies и `sessionToken`.

Worker ↔ main (`host-protocol.ts`): команды `lectures.getView`, `lectures.import`, `lectures.stopCurrent`, `lectures.setSkipped { jobId, occurrenceId, skipped }`, `lectures.setShowWindow { show }`, `system.resumed`; событие `lectures.changed { view }`.

Renderer ↔ main (`DesktopApi`): `lectures.getView()`, `lectures.importNow()`, `lectures.stopCurrent()`, `lectures.setSkipped(...)`, `lectures.onChanged(listener)`; `app.getShowLectureWindow()`, `app.setShowLectureWindow(show)`. Настройка `showLectureWindow` хранится в `settings.json` (по умолчанию `true`) и передаётся worker так же, как выбор браузера; повреждённое значение заменяется значением по умолчанию.

### Действия

- **Остановить:** `abort()` активного запуска. Контроллер жизненного цикла закрывает браузер и сохраняет `completed` с причиной `manual`. В то же вхождение лекция больше не входит.
- **Пропустить / Вернуть:** выставляет или снимает `suppressed` у одного вхождения импортированного задания. Обновление расписания сохраняет флаг. Пропущенное вхождение планировщик не запускает. Если пропускается идущая лекция, она сначала останавливается.

### Экраны

После `session_ready` вместо текущего экрана «Сессия активна» открывается главное окно:

1. **Статус:** «Сейчас идёт: <дисциплина>, до HH:MM · <статус>» с кнопкой «Остановить», либо «Ближайшая: <день> HH:MM <дисциплина>», либо «Онлайн-пар не найдено».
2. **Расписание:** время последнего обновления, кнопка «Обновить расписание», ход импорта по стадиям («Поиск группы», «Расписание», «Курсы СДО», «Лекции BBB», «Сохранение»), блок «Не удалось найти лекцию в СДО: …» при частичном результате, сообщение об ошибке с повтором.
3. **Список пар** по дням: время, дисциплина, статус последнего запуска, «Пропустить» или «Вернуть».
4. **Настройки** (свёрнуты): выбор браузера (`BrowserChoice`), «Показывать окно лекции», автозапуск, «Проверить вход».

Трей: подсказка и первая строка меню показывают текущее состояние («Лекция: <дисциплина>» или «Ближайшая: …»); пункты «Остановить лекцию» (только при активной лекции), «Открыть», «Выход».

### Граничные случаи

- Сеть или ТУСУР недоступны, страница расписания сломана (`ScheduleParseError`): `import.failed`, прежние пары сохраняются, в `core.log` пишется причина без HTML и секретов.
- Пробуждение после сна: немедленный `check()`; если окно пары уже закончилось, вход не выполняется, а в списке пара остаётся без запуска.
- Выход из приложения во время лекции: `abort()`, ожидание закрытия браузера не дольше 10 секунд, затем выход.
- Выбранный Chromium отсутствует: запуск не начинается, показывается существующий баннер установки; задания не теряются.
- Ошибки в снимке и логах проходят `redactSensitiveText`; join-URL и `activityUrl` в UI не показываются.

## Проверка

- Ядро: `import-service` (полный и частичный импорт, отсутствие prune при частичном, `auth_required` и ошибка без записи, стадии прогресса, транзакция при сбое записи, неизменный вывод CLI); `lecture-agenda` (сортировка, горизонт 14 дней, пропущенные вхождения, текущая и ближайшая лекция, часовой пояс).
- Worker: `SchedulerLoop` с фейковыми часами (тик, `resume`, одна лекция одновременно, остановка → `manual`, канал и `headless` из настроек); `ImportScheduler` (после входа, старше 24 ч, отсрочка во время лекции, повтор через час, один импорт на несколько команд); восстановление зависших запусков; `setSkipped`; остановка планировщика при `auth_required`.
- Main: меню трея по состоянию, выход во время лекции, пересылка `resume`, настройка окна лекции.
- Renderer: главный экран — текущая и ближайшая лекция, прогресс, нераспознанные дисциплины, «Пропустить/Вернуть», «Остановить».
- E2E (`CI_ELECTRON_E2E=1`): фиктивные сессия, импорт и runner — от входа до списка пар и остановки.
- Вручную на Windows: реальный импорт, вход на тестовую лекцию, «Остановить» из трея, сон и пробуждение.

## Риски

- BBB-адаптер пока распознаёт только состояние «подключён»; конец встречи и комната ожидания приводят к `failed/error`, пока не сняты фикстуры реальных страниц. Главное окно покажет такой исход как ошибку последнего запуска.
- Падение worker во время лекции оставляет пару без повторного входа (см. восстановление зависших запусков).
- Скрытый браузер может не подключить аудио BBB; по умолчанию окно лекции видимое.
